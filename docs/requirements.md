# 요구사항과 기본 가정

개발 기준은 사용자가 제공한 `assignment-hub_codex_prompt.md` 전체이며 [원문 사본](requirements-source.md)을 함께 보관합니다. 이 문서는 이번 구현의 범위와 기본값을 요약하며 실제 검증 여부는 `test-report.md`에서 별도로 관리합니다. GitHub 외부 저장소 생성·배포는 수행 범위에 포함하지 않습니다.

## 기능·정확성 범위

1. Streamlit, FastAPI, SQLite, 파일시스템, Caddy를 인스턴스별로 실행하며 외부 포트는 하나입니다. 내부 서비스는 loopback에 바인딩합니다.
2. 로컬에서 관리자 계정을 생성합니다. 수강생은 관리자가 TSV를 붙여넣거나 파일로 등록해 생성하고 임시비밀번호를 개별 발급합니다. 명단 반영 전 검증하고 기존 계정 수정은 명시적으로 선택합니다. 초기 원문의 `.xlsx` 입력 요구사항은 후속 TSV 입력 요청으로 대체합니다.
3. 최초 비밀번호 변경, 초기화·비활성화·로그아웃·만료를 API에서 강제합니다. 사용자는 자신의 작업에만 접근하고 관리자는 전체 완료 제출에 접근합니다.
4. 브라우저 `File.slice()`로 청크를 전송하고 서버는 제한된 메모리로 임시 파일에 기록합니다. Streamlit 파일 업로더는 작은 명단에만 사용합니다.
5. 묶음의 파일 목록을 시작 시 고정합니다. 전 파일의 크기·SHA-256 검증, 파일 동기화·이동, DB 커밋이 완료되어야 제출 완료로 표시합니다.
6. 동일 시작·청크·완료 요청은 재시도로 중복 제출·용량을 만들지 않습니다. 마지막 확정 offset을 영속 저장하고 재로그인·재선택 후 재개합니다.
7. 파일당 제한, 사용자 완료+예약 한도, 실제 볼륨 여유를 독립 검사합니다. 같은 사용자 동시 요청은 짧은 DB 트랜잭션으로 예약합니다.
8. 취소·만료된 미완료 작업은 파일과 예약을 함께 정리합니다. 완성된 제출은 자동 삭제하지 않습니다. 시작 후 접수가 종료된 유효 작업은 보관 시간 내 완료할 수 있습니다.
9. 관리자 집계의 제출자는 선택 과제에 완료 제출이 하나 이상 있는 활성 수강생입니다. 여러 버전을 여러 명으로 세지 않습니다. 비활성 계정의 기록은 보존합니다.
10. 저장 경로는 서버 UUID로 구성하고 파일 원본 이름은 메타데이터로 보존합니다. 다운로드는 인증 후 첨부 형태로 전달하며 제출 폴더를 정적 공개하지 않습니다.
11. 설치·관리 BAT, CLI, 두 설정 예제, 엑셀 템플릿, 운영 문서, 자동 테스트, 실제 대용량 검증 도구를 제공합니다.

## 경계와 운영자가 결정할 항목

접속 인원과 네트워크 대역폭이 정해져 있지 않아 전송 속도나 최대 인원을 보장하지 않습니다. 운영자는 IP/호스트, 포트, 바인딩, 저장 위치, 용량, 동시성, 보관·세션 시간, 시간대, HTTPS 구성을 조정합니다. HTTP는 네트워크 암호화를 제공하지 않습니다. 업로드 파일을 실행하거나 압축 해제하지 않으며 악성코드 검사·실시간 외부 백업·EXE 배포는 별도 운영 범위입니다.

검증 ID A01–E01의 세부 판정은 `test-report.md`를 참조합니다. 작은 파일·실패 주입의 통과를 실제 2GiB, 실제 Windows BAT, 실제 브라우저 검증으로 대체하지 않습니다.
