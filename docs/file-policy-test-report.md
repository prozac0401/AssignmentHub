# 파일 분류·영상 검사 검증

검증일: 2026-09-08. Windows x64, Python 3.12 개발 환경, PyAV 18.0.0, 실제 Edge 152.0.4191.66을 사용했습니다. 과제·계정·파일은 별도 테스트 저장소에서 생성했고 테스트 서버는 종료했습니다.

## 자동 검사

건너뛴 3개는 `AH_PORTABLE_ZIP`으로 새 배포 ZIP을 지정해야 실행되는 배포 이동·실행 검사입니다. 전체 검사에는 기존 AnyIO 관련 DeprecationWarning 1건이 있었으며 실패는 없었습니다.

주요 검증 범위:

- 기존 DB의 추가 마이그레이션·재실행, 기존 과제의 허용 분류 보존.
- 관리자 권한, 알 수 없는 분류·중복·잘못된 타입 거절, `[]` 전체 차단, `false` 및 부분 수정 보존.
- 과제별 독립 설정, 확장자 대소문자, 이중 확장자, 압축 금지 상태에서 기타 허용을 이용한 우회 차단.
- 전송 중·검증 직후·최종 이동 직후 정책 변경 시 확정 방지, 예약 해제, 이전 완료 제출의 다운로드 보존.
- 별도 프로세스에서 6초 영상의 첫 5초 및 0.4초 영상 전체 검사, MP4·MKV·WebM 디코딩.
- 무음, 음성 트랙 없음, 5초 이후에만 소리가 있는 영상, 소리 필수 해제 후 제출.
- 가짜 영상, 음성만 있는 MP4, 빈 파일, 잘린 컨테이너, 영상·음성 패킷 손상, 외부 참조 재생목록 거절.
- 검사 시간 초과·검사기 부재를 성공으로 처리하지 않음, 환경 복구 후 재시도.
- 서버 재시작 및 구버전의 `finalizing` 상태에서도 검사 생략 방지.
- Streamlit 설정 저장 후 압축 허용 켜기→끄기, 소리 필수 끄기→켜기, 모든 분류 끄기→다시 켜기.

화면 테스트로 과제를 dict 값으로 보관하면 저장 이후 이전 정책이 다시 쓰이는 문제를 재현했습니다. 과제 ID만 선택 상태에 보관하고 매번 최신 API 결과에서 설정을 읽도록 수정한 뒤 반복 변경이 통과했습니다.

## 실제 브라우저

```bat
.venv\Scripts\python.exe scripts\check_file_policy_browser.py --node <node.exe 경로>
```

[자동 결과 JSON](evidence/file-policy-browser.json): 아래 7개 시나리오 통과, JavaScript 오류 0건.

1. 관리자 화면에서 문서 전용 과제 생성.
2. 압축 허용 켜기·저장·끄기·저장 후 서버 값 확인.
3. 파일 선택과 드래그 앤 드롭에서 압축파일 차단, 문서 제출 완료.
4. MP4로 이름만 바꾼 파일 거절, 제출 완료 화면 없음.
5. 실제 영상 검사 후에만 제출번호와 첫 5초 검사 결과 표시.
6. 무음 영상 거절 및 관리자가 무음을 허용한 뒤 제출 성공.
7. 390×844 모바일 화면의 가로 넘침 없음.

## 범위

검사 구간 이후의 영상, 말소리의 명료도·내용 적절성, 압축 내부의 개별 파일은 검증 대상이 아닙니다. 검은 도입 화면은 경고로 안내합니다. 모든 코덱·8K·실제 2GiB 영상 성능, 새 배포 ZIP의 별도 PC 설치·실행은 이번에 검증하지 않았습니다. 기존 배포 ZIP을 수정하거나 새 릴리스를 게시하지 않았으며, 새 의존성을 포함한 배포본은 `build_portable.bat`로 빌드해야 합니다.
