# 관리자 운영 안내

[2쪽 퀵가이드 PDF](manual/AssignmentHub_퀵가이드.pdf)에서 운영자용 절차를 먼저 확인할 수 있습니다. 상세 화면과 상황별 예시는 [시나리오별 매뉴얼](manual/scenarios.md)을 참고하세요.

## 설치·생성·설정

일상적인 운영은 `start.bat`를 더블클릭해 **서버 관리창**에서 진행할 수 있습니다. 새 과정 만들기, 기존 설정 추가, 시작·중지, 주소 복사, 폴더 열기, 접속 점검을 제공합니다. 관리창을 닫아도 서버는 유지됩니다. 자세한 단계는 [서버 관리창 안내](server-manager.md)를 참고하세요. 아래 CLI 명령도 그대로 사용할 수 있습니다.

배포 ZIP에는 Python 3.12 x64, Tcl/Tk, 고정 의존성, Caddy, 정적 자산과 TSV 템플릿이 포함됩니다. 전체 압축을 해제한 뒤 `start.bat`만 실행하면 됩니다. Python·관련 라이브러리 설치와 인터넷 연결은 필요하지 않습니다. `setup.bat`는 파일 해시와 구성요소를 확인하는 선택적인 오프라인 점검입니다. 소스에서 배포본을 만드는 절차는 [무설치 배포 안내](portable-distribution.md)를 참고하세요.

```bat
manage.bat create --config instances\course_01.json --instance-id course_01 --course-name "교육과정 1차" --port 8501 --public-host 192.168.0.10 --storage-root D:\Assignments\course_01 --admin-id admin
manage.bat validate --config instances\course_01.json
manage.bat start --config instances\course_01.json
manage.bat status --config instances\course_01.json --json
manage.bat stop --config instances\course_01.json
manage.bat configure --config instances\course_01.json --port 8503 --public-host 192.168.0.20
```

생성 시 비밀번호는 로컬 콘솔에서 입력하며 명령줄에 넣지 않습니다. 최초 관리자를 네트워크 첫 방문자가 생성할 수 없습니다. 실행 중 설정을 변경하지 말고 먼저 해당 인스턴스를 중지하세요. 설정 오류, 중복 실행, 저장 루트 충돌, 쓰기 권한, 포트 사용, 디스크 공간 오류는 고친 뒤 다시 실행합니다. `--public-host`는 여러 네트워크 인터페이스 중 수강생이 접근할 주소로 지정합니다.

관리자 권한은 최초 로컬 설정에서 부여합니다. 수강생 명단으로 관리자 권한을 부여하지 않습니다.

## 명단 등록과 임시비밀번호

1. `templates/users_template.tsv`의 예시를 실제 명단으로 바꿉니다. 첫 행은 탭으로 구분한 `user_id`, `name`, `group`입니다. `user_id`와 `name`은 필수이며 `group`은 선택입니다. 모든 ID를 텍스트로 읽으므로 `001`과 `1`은 서로 다른 계정입니다.
2. 관리자 화면 명단 등록에서 **직접 붙여넣기**에 헤더와 명단을 입력하거나 **TSV 파일 업로드**로 `.tsv`/`.txt` 파일을 선택합니다. 엑셀·스프레드시트의 셀 범위를 복사해 붙여넣어도 됩니다. 미리보기에서 빈 ID/이름, 명단 내 중복, 필수 열 누락, 열 수 오류와 기존 계정 여부를 확인합니다. 명단을 고치거나 입력 방법을 바꾸면 이전 미리보기는 해제되므로 다시 검증하세요.
3. 새 계정은 추가합니다. 기존 이름·그룹을 변경하려면 해당 옵션을 명시적으로 선택합니다. 재등록은 비밀번호 초기화가 아니며 기존 제출·활성 상태를 유지합니다.
4. 기본값은 개인별 임시비밀번호 자동 발급이며, 영문·숫자 8자리(8바이트)입니다. 차수 공통값을 쓰려면 명단 반영 전에 **신규 수강생에게 공통 임시비밀번호 사용**을 켜고 **이 차수의 공통 임시비밀번호**에 영문·숫자 8자리를 입력합니다. 이번 명단의 신규 계정에만 적용합니다. 추가 등록 시 같은 값을 다시 입력하며 기존 계정의 비밀번호는 유지합니다.
5. 적용 직후 표시되는 임시비밀번호 결과 CSV를 내려받아 본인 ID와 함께 전달합니다. 평문 결과는 일반 로그나 DB 설정에 보존하지 않으므로 분실한 사용자는 개별 초기화합니다. 학생은 첫 로그인 후 8~128자의 개인 비밀번호로 변경합니다. 초기화할 때는 새 개인별 8자리를 발급합니다.

ID는 공백을 제거한 뒤 대소문자를 구분합니다. `001`, `1`, `Abc`, `abc`는 서로 다른 ID입니다. 엑셀에서 이미 숫자로 바뀌어 사라진 0을 서버가 추정하지는 않으므로 복사 전 ID 열을 텍스트로 유지하세요. 명단 파일은 UTF-8(BOM 선택) 또는 UTF-16(BOM 필수)로 저장합니다. 최대 5MiB, 10,000명, 30열이며 빈 행은 무시합니다. 탭이나 줄바꿈이 포함된 셀은 큰따옴표로 감싸고 셀 안의 큰따옴표는 두 번 씁니다. `.xlsx` 명단 입력은 지원하지 않습니다. 실제 명단·비밀번호 결과·계정 DB·파일·로그·비밀값은 Git에 추가하지 않습니다.

명단 입력은 수강생 계정을 일괄 등록하고 기존 이름·그룹을 갱신하는 기능입니다. 수강생이 제출하는 과제 파일은 기존처럼 엑셀을 포함한 여러 파일 형식을 사용할 수 있습니다.

## 계정·과제·제출 현황

사용자 검색에서 계정을 활성·비활성화하거나 비밀번호를 초기화합니다. 초기화하면 새 임시비밀번호를 발급하고 이전 세션 및 업로드 권한을 즉시 무효화합니다. 비활성 계정의 완료 제출 이력은 삭제하지 않습니다.

과제 관리에서 제목·설명·접수 상태를 수정합니다. 접수를 닫으면 신규 제출을 막습니다. 종료 전에 시작한 유효 업로드는 24시간 보관 정책 안에서 완료할 수 있습니다. 계정 비활성화·초기화 제한은 즉시 적용됩니다.

과제별 대상자는 활성 수강생이며 관리자는 제외합니다. 완료 제출이 하나 이상 있는 사용자가 제출자입니다. 재제출이 여러 건이어도 제출자는 한 명입니다. 업로드 중·검증 중·실패한 작업만 있는 사용자는 미제출자입니다. 검색·그룹 필터, 최신 및 이전 완료 이력, 파일 목록, 바이트 용량, 제출번호·버전·시각, 저장 경로를 확인하고 현황을 내보낼 수 있습니다. 비활성 사용자 기록은 별도 포함해서 조회합니다.

완료 파일은 권한 검사 후 다운로드합니다. 원본 이름이 같아도 각 제출 버전은 다른 파일로 보존합니다. CSV는 Excel 수식 실행을 막는 텍스트 이스케이프를 적용하며 시각의 시간대를 명시합니다.

## 디스크·오류·정리

완료 사용량, 진행 예약, 실제 임시 바이트, 실제 볼륨 여유는 서로 다른 수치입니다. 사용자 한도는 과제·버전을 모두 합합니다. 시작 시 공간이 충분해도 다른 인스턴스나 프로그램이 공간을 소비할 수 있습니다. 공간 부족 안내가 나면 공간을 확보하거나 저장 정책을 조정하고 미완료 작업을 재개·취소합니다. 운영 볼륨을 실제로 가득 채워 시험하지 마세요.

미완료 취소·만료는 임시 파일과 예약을 정리합니다. 활성 작업은 청크 처리와 잠금으로 충돌을 피하고 완료 파일은 자동 삭제하지 않습니다. 파일 이동·DB 오류가 나면 제출 성공으로 안내하지 않습니다. 사용자에게 서버 상태 확인 후 같은 작업을 재시도하도록 안내하세요. 다운로드 시 파일 누락·크기 변경을 검출합니다. 같은 크기의 외부 내용 변경은 자동으로 검출하지 않으므로 저장 루트를 직접 수정하지 말고 백업 복원 및 SHA-256 비교를 사용합니다.

## 정상 종료 후 백업·복원

`storage_root`에는 다음 항목을 보관합니다. 완료 경로의 UUID는 내부 식별자이며 관리자 화면에서 과제·수강생·제출번호·원본 파일명과 대응시켜 확인합니다.

```text
storage_root/
  instance.json       인스턴스 식별 정보
  assignmenthub.db     계정·과제·업로드·제출·예약·관리 기록
  auth.secret         인스턴스별 인증 비밀값
  tmp/                미완료 청크 파일
  submissions/        완료 파일 (서버 생성 식별자로 구분)
  logs/               실행·API·Streamlit·프록시 로그
  runtime.json        해당 실행의 프로세스 식별 정보
  Caddyfile           실행 도구가 만든 게이트웨이 설정
  proxy-config/       이 인스턴스의 Caddy 설정 상태
  proxy-data/         이 인스턴스의 Caddy 저장 상태
```

인스턴스 설정 JSON은 생성 명령의 `--config` 경로에 별도로 저장합니다.

1. 해당 인스턴스에서 신규 접수를 닫고 업로드 완료를 기다리거나 사용자에게 중단을 안내합니다.
2. `manage.bat stop --config instances\course_01.json` 후 `status`가 중지됨인지 확인합니다. 다른 인스턴스는 계속 실행할 수 있습니다.
3. 설정 JSON과 `storage_root` 전체(DB, WAL/SHM가 남아 있으면 포함, 완료 파일, 임시 파일, 인스턴스 식별 정보, 인증 비밀값, 로그)를 같은 백업 시점으로 복사합니다. 실행 중 DB 파일만 복사하지 않습니다.
4. 복원 대상 인스턴스를 중지한 상태에서 빈 별도 폴더에 전체 백업을 복원하고 설정의 저장 경로·안내 IP·포트를 확인합니다. 비밀값과 DB를 서로 다른 시점의 것으로 섞지 않습니다.
5. `validate`, `start`, `status`를 실행하고 계정 로그인, 제출 목록, 대표 파일 다운로드의 크기·해시를 확인한 후 접수를 엽니다.

하드웨어·전원 장애는 프로세스 재시작 복구보다 넓은 범위입니다. 백업 복원 훈련을 별도 PC/폴더에서 수행하고 결과를 기록하세요.

## HTTP·TLS·접속 보호

HTTP 기본 설정은 교육장 네트워크 내 기능 검증을 위한 가정이며 네트워크 전송을 암호화하지 않습니다. HTTPS는 설정의 `secure_cookies=true`, `tls_cert_file`, `tls_key_file`에 조직이 제공한 인증서·개인키 경로를 지정하면 인스턴스 Caddy에서 종료합니다. 인증서의 호스트명이 `public_host`와 일치하고 수강생 PC가 발급 기관을 신뢰해야 합니다. 개인키는 Git에 넣지 않습니다. 설정의 외부 HTTPS 주소와 실제 접속 origin을 일치시키고 HTTP/WebSocket을 함께 검증하세요. CORS나 Streamlit XSRF 보호를 끄는 방식으로 접속 문제를 해결하지 않습니다. 내부 API·Streamlit 포트를 외부 공개하지 마세요.
