# AssignmentHub v1.4.0

2026-09-23 배포. Windows 10/11 x64용 내장 Python·Tcl/Tk·라이브러리·Caddy를 포함합니다.

## 주요 변경

- **과제별 파일 정책:** 문서·스프레드시트·발표자료·이미지·영상·음성·압축파일·코드·기타를 개별 허용합니다. 영상은 첫 5초의 재생·음성을 검사하며, 소리 필수 여부를 설정할 수 있습니다. 새 기본 과제도 동일한 기본 정책을 사용합니다.
- **제출물 관리:** 수강생별 최신 제출, 파일명 검색, 이전 버전, 파일별 CSV, 수강생 이름과 버전을 포함한 다운로드 파일명을 제공합니다. 저장 폴더는 과제·수강생·접수 순번과 원본 파일명을 사용합니다.
- **복구 가능한 명단 등록:** 대량 명단을 백그라운드에서 처리하고 진행 인원을 표시합니다. 재접속·재로그인·서버 재시작 후 동일 결과를 조회하며, 동일 요청 재전송으로 중복 계정을 만들지 않습니다.
- **임시비밀번호 보관:** 작업별 키로 암호화하고 완료 후 1시간 동안 조회할 수 있습니다. CSV 저장 후 결과를 닫거나 보관 시간이 만료되면 결과와 복구 키를 삭제합니다.
- **로그인·업로드 안정성:** 접속자별 로그인 제한을 분리하고 전달 헤더 위조를 막습니다. 파일 I/O 오류에도 전송 슬롯을 반환하며, 디스크 예약량 확인 시 전체 미완료 파일 순회를 제거했습니다.
- **명단 크기 일치:** 유효한 TSV가 JSON 변환 때문에 반영 단계에서 거절되던 제한 불일치를 수정했습니다. 큰 명단 요청은 본문 처리 전에 인증합니다.

## 기존 서버 업그레이드

1. 기존 관리창에서 서버를 중지합니다. 설정 JSON과 저장 루트 전체(DB·제출 파일·비밀값 포함)를 함께 백업합니다.
2. `AssignmentHub-1.4.0-windows-x64.zip` 전체를 **새 폴더**에 압축 해제합니다. 기존 실행 폴더에 일부 파일만 덮어쓰지 않습니다.
3. 새 폴더의 `start.bat`를 실행하고 **기존 설정 추가**로 기존 JSON을 연결합니다. `storage_root`가 원래 저장 루트를 가리키는지 확인합니다.
4. 서버를 시작합니다. 기존 제출 파일을 읽기 쉬운 경로로 전환하고 DB에 필요한 구조를 추가합니다. 파일 수에 따라 첫 시작 시간이 달라질 수 있습니다. 기존 파일 허용 정책은 유지됩니다.
5. 과제 정책, 최근 제출 다운로드, 수강생 접속을 확인합니다. 이전에 열어 둔 수업·제출 창은 새로 엽니다.

전환 후 구버전으로 돌아가야 한다면 서버를 중지하고 **전환 전 백업의 DB·파일·비밀값 전체를 함께 복원**합니다. 새 DB와 이전 파일 폴더를 섞지 않습니다. 같은 저장 루트에 이전 서버와 새 서버를 동시에 실행하지 않습니다.

운영 PC에 Python이나 FFmpeg를 별도로 설치할 필요는 없습니다. 배포 폴더의 `setup.bat`로 내장 라이브러리와 파일 해시를 점검할 수 있습니다.

## 외부 API와 문서

대량 명단 클라이언트는 `/api/admin/roster/jobs`의 접수·상태·결과 조회·수신 확인 흐름을 사용하세요. 기존 `/api/admin/roster/apply`는 동기식 호환 API로 유지됩니다. API 경로의 말미 `/`가 다르면 자동 리다이렉트 없이 404를 반환합니다. [API 참조](../api.md)

동봉된 PDF·PPTX·퀵가이드는 v1.3.0 기본 절차 자료입니다. 이번 변경은 [관리자 안내](../admin-guide.md), [파일 정책](../file-policy.md), [제출 저장 규칙](../submission-storage.md), 웹·텍스트 매뉴얼에서 확인하세요.
