# AssignmentHub v1.4.1

2026-10-03 · v1.4.0 기준의 업로드 취소 버튼 동기화 수정입니다.

새로고침 후 **이 작업 이어 올리기**를 선택하면 원본 파일을 다시 고르기 전에도
**업로드 취소**를 사용할 수 있습니다. 파일 재선택 없이 취소하려는 작업을 정리할 수
있으며, 작업 선택만으로 취소하지 않습니다. 제출 재개에는 원본 파일이 필요합니다.

기존 취소 API·인증·소유권 검사·저장·예약 정책, 과제 잠금과 완료·실패·취소·만료 상태의
취소 숨김 조건은 유지합니다. 데이터 구조와 의존성은 바꾸지 않았습니다.

## 실행과 업데이트

`AssignmentHub-1.4.1-windows-x64.zip` 전체를 새 폴더에 압축 해제하고 `start.bat`를 실행하세요.
Windows x64 내장 Python·Tcl/Tk·라이브러리·Caddy를 제공합니다.
기존 서버는 중지하고 설정 JSON과 저장 루트 전체(DB·제출 파일·비밀값)를 함께 백업한 뒤,
새 관리창에서 **기존 설정 추가**로 같은 JSON을 연결합니다. 이전 제출 창은 새로 여세요.
v1.4.0 이전 버전에서 올리는 경우 [v1.4.0 업그레이드 안내](v1.4.0.md)를 함께 따릅니다.

## 이번 검증

- DOM/API 모의 검사 13 PASS. Windows Node 24.19.0.
- 실제 Edge 154.0.4258.48의 합성 API 브라우저 검사 13 PASS. 실제 서버의 용량 반환을 입증하는 검사는 아닙니다.
- 실제 서버 API의 예약·취소 회귀 1 PASS, 24 deselected. 전체 Python suite 결과가 아닙니다.
- Windows 11 / CPython 3.12.14에서 기존 빌더로 ZIP을 제작했습니다. 고정 wheel 해시 및 내장 런타임·Tk·Caddy 2.10.2 확인 통과.
- 제작 ZIP의 배포 검사 3 PASS, 1 deselected: 무결성, 한글·공백 경로 이동, 시스템 Python 탐색·외부 다운로드를 차단한 BAT·CLI, 실제 서버 시작·제출·재시작·종료. 관리창 전체 GUI 회귀는 반복하지 않았습니다.
- 실제 로컬 FastAPI와 인앱 브라우저에서 새로고침 → 복구 선택 → 파일 0개 → 명시적 취소를 확인했습니다. 취소 버튼 표시, 재개 비활성화·과제 잠금 유지, 선택 시 변경 요청 0회, 취소 POST 1회/200, 예약 0·임시 파일 삭제·타인 접근 404·기존 완료 파일 보존을 확인했습니다. 운영 계정·운영 저장소는 사용하지 않았습니다.
- 별도의 합성 API 작업에서 취소 잠금 409일 때 예약·임시 파일을 보존하고, 잠금 해제 후 명시적 재시도 200으로 정리되는 것을 확인했습니다. UI 자동 재시도 검증은 아닙니다.
- 최종 ZIP은 동일한 런타임·의존성을 보존하고 확정한 공개 소스·문서를 반영합니다. 소스 대조·전 파일 해시·ZIP CRC 결과와 최종 체크섬은 릴리스 본문에 기록합니다.

과거 v1.4.0의 전체 Python 219 PASS와 기존 수동 시험은 당시 근거입니다. 이번 패치에서
전체 suite·전체 GUI·운영 데이터 업그레이드·원격 교육장·2GiB 부하를 반복하지 않습니다.
CI는 구성되어 있지 않습니다. 이번 결과를 별도 Windows 10/새 PC의 시험 성공으로 확대하지 않습니다.

최종 소스 SHA, ZIP SHA-256과 실제 실행·미실행 범위는 릴리스 본문 및 ZIP의 체크섬으로 연결합니다.
운영 데이터·개인 설정·원시 로그는 릴리스 자산에 포함하지 않습니다.
