# 과제별 파일 분류와 영상 검사

관리자 **과제 관리 → 새 과제 추가 / 수정할 과제 → 허용할 제출 파일**에서 분류를 각각 체크하거나 해제하고 저장합니다. 문서 과제는 **문서**만, 발표 녹화 과제는 **영상**만 선택합니다. 압축 제출을 받으려면 **압축파일**을 추가로 선택합니다. 모두 해제하면 신규 파일 제출과 진행 중인 제출의 확정을 막습니다.

[실제 설정 화면](evidence/file-policy-admin.png) · [검증 결과](file-policy-test-report.md)

| 분류 | 주요 확장자 |
| --- | --- |
| 문서 | PDF, HWP, HWPX, DOC, DOCX, ODT, RTF, TXT, MD, PAGES, EPUB |
| 스프레드시트 | XLS, XLSX, XLSM, XLSB, ODS, CSV, TSV, NUMBERS |
| 발표자료 | PPT, PPTX, PPS, PPSX, ODP, KEY |
| 이미지 | JPG, JPEG, PNG, GIF, BMP, WEBP, SVG, TIF, TIFF, HEIC, HEIF, AVIF, PSD, AI |
| 영상 | MP4, MOV, M4V, AVI, MKV, WEBM, WMV, MPG, MPEG, MTS, M2TS, FLV, OGV, 3GP, 3G2, VOB |
| 음성·음악 | MP3, WAV, M4A, AAC, FLAC, OGG, OPUS, WMA, AIF, AIFF, AMR |
| 압축파일 | ZIP, 7Z, RAR, TAR, GZ, TGZ, BZ2, XZ, ALZ, EGG |
| 코드·데이터 | PY, IPYNB, JS, TS, JSX, TSX, HTML, CSS, JSON, XML, YAML, SQL, R, C, CPP, JAVA 등 |
| 기타 | 위 분류에 없는 확장자와 확장자 없는 파일 |

전체 확장자는 제출 화면의 **허용 확장자 보기**와 관리 화면 체크박스의 도움말에서 확인합니다. `.ts`는 TypeScript 코드 분류입니다. 확장자는 대소문자를 구분하지 않습니다. **기타**를 켜도 해제된 문서·영상·압축 등의 분류는 허용되지 않습니다.

파일 분류는 파일명 확장자를 기준으로 합니다. 문서·이미지·코드 등의 내부 내용이나 압축파일 안의 개별 파일을 검사하는 기능은 아닙니다. 개별 영상을 반드시 검사해야 하는 과제는 **압축파일**을 해제하고 영상 원본으로 받으세요.

## 영상 검사와 소리 설정

영상은 기존의 이어 올리기 방식으로 서버의 임시 저장 공간에 수신한 후, **제출번호를 발급하기 전** 검사합니다. 파일 전체의 크기·SHA-256 확인과 함께 첫 5초의 화면과 음성을 실제로 디코딩합니다. 영상이 5초보다 짧으면 전체 구간을 검사합니다. 브라우저의 코덱 지원 여부에 의존하지 않습니다.

- 화면 프레임 없음, 디코딩 오류, 시작 구간의 손상·잘림, 가짜 영상 파일은 거절합니다.
- **영상에 소리 필수**는 기본으로 켜져 있습니다. 검사 구간의 음성 신호가 없거나 무음에 가까우면 거절합니다. 첫 5초 이후에만 소리가 나는 영상도 이 설정에서는 거절합니다.
- 무음 화면 녹화나 애니메이션을 받으려면 **영상에 소리 필수**를 해제합니다. 음성 트랙이 없는 영상도 받을 수 있지만, 존재하는 화면·음성 데이터의 읽기 오류는 계속 거절합니다.
- 정상적으로 디코딩되지만 처음부터 검은 화면인 영상은 안내를 표시합니다. 의도한 도입 화면일 수 있으므로 검은 화면만으로 차단하지 않습니다.
- 완료 화면과 제출 이력에서 검사 시간, 화면 확인, 소리 확인 또는 무음 허용 결과를 볼 수 있습니다.

음성은 검사 구간 RMS 기준 `-60 dBFS` 이상인 신호가 있는지 판단합니다. 사람의 말이 명료한지, 잡음인지, 내용이 과제에 적절한지 판정하지 않습니다. 검사 구간 이후의 전체 재생 상태도 보장하지 않습니다.

검사에 실패하면 해당 묶음을 완료 제출로 집계하지 않고 임시 파일과 예약 용량을 정리합니다. 원본을 확인하거나 다시 인코딩한 뒤 **새 제출로 전환**하여 올립니다. 이전에 완료된 제출은 유지됩니다. 검사기를 실행할 수 없는 서버 오류는 실패 파일로 단정하지 않고 임시 파일을 보관하므로, 서버 점검 후 같은 작업을 재시도할 수 있습니다.

## 기존 과제와 운영 환경

기존 DB는 시작 시 컬럼을 추가하며 과제·계정·제출 이력·완료 파일을 유지합니다. 이전 과제는 기존의 제한 없는 접수를 보존하기 위해 기타를 포함한 모든 분류가 허용됩니다. 관리자 화면에서 필요한 분류만 남기세요. 새로 추가하는 과제와 새 과정에 자동으로 만들어지는 **기본 과제**는 모두 기타를 제외한 일반 분류가 기본 선택됩니다. 이미 존재하는 과제의 설정은 재시작해도 바꾸지 않습니다.

허용 분류와 소리 필수 설정 변경은 **아직 완료되지 않은 제출에도 확정 시 적용**합니다. 이미 완료된 제출의 조회·다운로드는 영향을 받지 않습니다. 접수 종료 전에 시작한 작업을 이어 올릴 수 있는 기존 규칙도 유지되며, 확정 시 현재 파일 정책을 통과해야 합니다.

개발 환경은 `requirements.lock`을 설치합니다. 배포 빌드에도 해시를 고정한 `av==18.0.0`이 포함되고 오프라인 점검에서 네이티브 모듈을 확인합니다. [PyAV의 공식 배포 안내](https://github.com/PyAV-Org/PyAV#installation)에 따라 FFmpeg를 포함한 wheel을 사용하므로 운영 PC에 FFmpeg를 별도로 설치할 필요가 없습니다. 기존 ZIP에 소스 파일만 덮어쓰지 말고, 새 의존성을 포함하여 빌드한 배포본을 사용하세요.

영상 검사는 별도 로컬 프로세스로 실행하며 파일당 최대 45초, 동시 최대 2개(설정된 전송 동시성이 1이면 1개)입니다. 검사 대기는 재시도할 수 있고 제한 시간 내에 검사하지 못한 파일은 등록하지 않습니다. 외부 파일·주소를 참조하는 재생목록은 허용하지 않습니다. 디코딩 해상도는 최대 33,554,432픽셀(8K 수준)이며 모든 영상 데이터를 메모리에 올리지 않습니다. 파일이 외부 서비스로 전송되지 않습니다.
