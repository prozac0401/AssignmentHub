# 제출물 저장 및 확인

## 서버 저장 경로

새 제출은 아래 형식으로 저장합니다.

```text
submissions/
  과제-1_기본 과제/
    홍길동_001_수강생-2/
      접수-000001/
        실습 결과.txt
        실습 결과 (2).txt

tmp/
  홍길동_001_수강생-2_접수-000002/
    실습 결과.txt.part
```

과제명, 수강생 이름·로그인 ID, 원본 파일명을 사용합니다. 과제·수강생 뒤의 숫자는 동명·대소문자 차이·이름 정리 후 충돌을 구분하는 서버 내부 순번입니다. 접수 순번은 업로드를 시작할 때 정하며, 완료 시 부여되는 제출번호·버전과는 별개입니다. 다른 제출과 재제출은 별도 폴더에 보존합니다.

Windows에서 사용할 수 없는 경로 구분자·예약문자·예약 이름은 치환합니다. 한글은 NFC로 정규화합니다. 저장 기본 파일명은 UTF-16 기준 120자, 과제명은 40자, 수강생 이름은 32자, ID는 24자까지 사용하며 긴 이름은 줄이고 확장자를 보존합니다(긴 이름을 줄일 때 확장자는 최대 20자). 같은 폴더에서 이름이 겹치면 확장자 앞에 `(2)`, `(3)` 등을 붙입니다. 원본 파일명 전체는 DB와 조회 화면에 남습니다.

이름은 접수 당시 값으로 고정합니다. 이후 명단·과제명을 수정해도 기존 경로와 파일은 이동하지 않으며, 화면에는 현재 명단의 이름을 표시합니다. 인증용 식별자·비밀번호 해시와 파일 전송 내용 비교용 SHA-256은 유지합니다.

## 기존 데이터 적용

수정된 서버를 시작하면 기존 저장 경로를 자동 전환합니다. 완료 파일과 유효한 미완료 파일 모두 대상입니다. DB에 경로 계획을 먼저 저장하고 같은 저장 루트 안에서 파일을 옮깁니다. 파일 내용, 제출번호, 버전, 용량 집계는 바꾸지 않습니다. 전환 도중 프로세스가 중단되면 다음 시작 때 남은 파일을 전환합니다.

대상 위치에 다른 파일이 이미 있으면 덮어쓰지 않고 서버 시작을 중단해 충돌 경로를 알립니다. 권한·경로 오류도 시작 로그에서 확인할 수 있습니다. 누락된 기존 파일을 복원하는 기능은 아닙니다. 전환 전에 서버를 중지하고 설정 파일과 저장 루트 전체를 백업하세요. 전환 후에는 이전 프로그램 버전이 새 저장 경로를 이해하지 못하므로, 되돌릴 때는 이전 프로그램과 전환 전 백업을 함께 복원합니다.

## 운영 담당자의 확인 순서

1. **제출 현황**에서 과제를 선택하고 이름·ID·그룹으로 조회합니다. 상단 집계는 검색과 관계없이 과제 전체 기준입니다.
2. **제출 파일 확인**에서 수강생별 최신 완료 버전과 파일명을 확인합니다. **이전 완료 버전도 표시**를 켜면 보존 이력을 포함합니다.
3. 파일명 검색과 최근 제출순·이름순 정렬로 제출물을 찾습니다. 미제출자 필터에서는 완료 파일을 표시하지 않습니다.
4. **확인할 제출**을 선택하면 원본 파일명·크기·서버 경로·다운로드가 표시됩니다. 서버 경로는 운영자 PC의 파일 탐색기에서 사용할 수 있습니다.
5. 운영자 다운로드 파일명은 `홍길동_001_제출-000001_v1_실습 결과.txt` 형식입니다. 수강생 다운로드는 원본 파일명을 사용합니다.
6. **현재 파일 목록 CSV 다운로드**는 현재 검색·버전 조건에 맞는 파일을 한 행씩 내보냅니다. 이름·ID·과제·제출번호·버전·시각·원본 파일명·크기·저장 경로를 포함합니다. **이 과제의 전체 현황 CSV 준비**는 비활성 계정과 이전 버전을 포함한 과제 전체 내보내기입니다.

저장 폴더에 있는 파일은 읽거나 복사해서 확인할 수 있습니다. 원본 경로에서 이름을 바꾸거나 편집·삭제하면 다운로드와 기록의 대응이 깨질 수 있으므로, 편집이 필요하면 다운로드하거나 별도 위치로 복사합니다.
