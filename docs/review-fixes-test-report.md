# 프로젝트 리뷰 개선 반영 및 검증

검증일: 2026-09-22. Windows x64, Python 3.12, 로컬 Caddy·FastAPI·Streamlit 및 Microsoft Edge 환경에서 확인했습니다. 기존 작업 내용을 유지하면서 리뷰에서 확인한 여섯 가지 문제를 수정했습니다.

## 반영 내용

| 문제 | 수정 및 확인 |
| --- | --- |
| 대량 명단 등록 중 화면의 60초 요청 제한으로 임시비밀번호 유실 | UI를 지속 가능한 비동기 명단 작업으로 전환했습니다. 같은 요청 ID 재전송은 같은 작업을 반환합니다. 계정 생성과 암호화 결과를 함께 커밋하며, 재로그인·서버 재시작 후 결과를 조회할 수 있습니다. |
| 청크 파일 닫기 오류 이후 업로드 슬롯 누수 | 파일 닫기 오류가 발생해도 제출 잠금과 전송 슬롯을 반환하도록 정리 순서를 보장했습니다. 실패한 쓰기·롤백·닫기 후 같은 offset 재전송과 다른 제출 진행을 검증했습니다. |
| 모든 Streamlit 사용자가 loopback 로그인 제한을 공유 | Caddy가 확인한 접속 IP를 내부 비밀값과 요청별 서명으로 전달합니다. API는 실제 loopback 연결과 서명을 검증하며, 사용자가 보낸 전달 헤더를 신뢰하지 않습니다. 계정별 제한도 유지합니다. |
| 매 청크 블록마다 모든 미완료 파일의 저장 경로 순회 | SQLite 트랜잭션에서 남은 예약량을 관리하고, 현재 전송 중인 파일만 조회합니다. 물리 쓰기와 임시 예약량 보정을 동기화하고 재시작 시 확정 offset으로 예약량을 복원합니다. |
| TSV 미리보기 성공 후 JSON 요청 크기 초과 | TSV 5MiB·최대 10,000행 규칙에 맞춰 JSON 변환의 최악 크기를 수용합니다. 큰 본문을 읽기 전에 관리자 인증을 확인하며, 동시 명단 본문 처리 수를 제한합니다. |
| 최초 기본 과제와 API 생성 과제의 파일 정책 불일치 | 새 저장소의 기본 과제도 신규 과제 정책을 사용해 기본적으로 ‘기타’를 제외합니다. 기존 과제의 허용 정책은 유지합니다. |

로그인 수정 과정에서 HTTPS 접속의 잘못된 API 슬래시가 내부 HTTP 주소로 리다이렉트될 수 있는 경우도 막았습니다. 정확하지 않은 API 경로는 리다이렉트 없이 404를 반환합니다.

## 결과 보관과 운영

- 명단 작업 입력과 임시비밀번호 결과는 개별 키로 암호화합니다. 대기 작업은 접수 후 1시간, 완료 결과는 완료 후 1시간 동안 보관합니다.
- 결과 닫기, 만료, 관리자 권한 변경 시 복구 키와 암호화 내용을 삭제합니다. 같은 요청 ID의 기록은 남겨 재전송으로 계정이 다시 생성되지 않도록 합니다.
- 계정 소유권과 권한 변경 시점을 검사하며, 작업·보관 용량 제한으로 누적 요청을 제어합니다. 유효한 결과는 오래된 실패 알림에 가려지지 않습니다.
- 기존 동기식 `/api/admin/roster/apply`는 호환성을 위해 유지합니다. 재접속 복구가 필요한 외부 클라이언트는 `/api/admin/roster/jobs`를 사용해야 합니다.
- 새 의존성 `cryptography==50.0.1`을 해시와 함께 고정했습니다. 소스 환경은 갱신된 의존성을 설치하고 서버를 재시작해야 합니다. 기존 배포 ZIP에는 이번 변경이 포함되지 않으며, 배포하려면 다시 빌드해야 합니다.

## 검증 범위

이번 실행은 16MiB 파일과 소형 장애 주입으로 업로드 동작을 확인했습니다. 실제 2GiB 파일 부하, 원격 교육장 네트워크, 수정된 배포 ZIP의 오프라인 설치는 이번 실행 범위에 포함하지 않았습니다. 기존 PDF·PPTX 매뉴얼은 재생성하지 않았으며, 변경된 명단 보관 정책은 관리자 안내와 웹·텍스트 매뉴얼에 반영했습니다.
